Test Account Setup
Before you begin: Use a dedicated QA investor account. Do not use a production investor account with real funds. Ensure cookies are enabled in the browser. Use an incognito / private-browsing window to start with a clean session and avoid cached auth tokens.

Password [password]
Browser Chrome / Firefox / Safari (latest)
Mode Incognito / Private window
Cookies required: The session token is stored in an HttpOnly cookie. Blocking cookies will prevent login. Disable any browser extensions that intercept cookies before testing.

1.6 Reload the page (F5) while logged in Session persists; dashboard reloads without redirect to login page □
1.7 Click Logout / Sign out from the account menu Session cookie is cleared; user is redirected to the login page □

Onboarding Checklist
Purpose: Verify that a brand-new investor account is guided through each onboarding step in the correct order and that the progress indicator updates after each completed step.
# Step Expected Result Pass / Fail Notes
2.1 Log in with a freshly created (not yet onboarded) test account Onboarding wizard / checklist screen is displayed; dashboard widgets are locked or greyed out until onboarding is complete □
2.2 FICA Upload — Upload a test ID document (dummy PDF or JPG, under 5 MB) Upload progress indicator shows; file appears in the uploaded documents list; step marked as complete with a green tick □
2.3 FICA Upload — Attempt to upload a file over 10 MB or an unsupported format (e.g. .exe) Error message displayed; upload is rejected; step remains incomplete □
2.4 Bank Account Details — Enter valid South African bank account details (account number, branch code, bank name) Details saved successfully; confirmation message shown; step marked complete □
2.5 Bank Account Details — Submit with an invalid branch code (e.g. "000") Validation error on branch code field; form does not submit □
2.6 Wallet Top-up — Navigate to the top-up step and initiate a deposit of R100 using the EFT option EFT banking details (account number, reference) are displayed; step status shows "Pending" or "Awaiting payment" □
2.7 First Investment — Attempt to reach this step without completing prior steps Step is locked; prompt directs user to complete preceding steps first □
2.8 With all prior steps complete, navigate to the First Investment step Available investment pools are listed; user can select a pool and enter an investment amount □
2.9 Refresh the page mid-onboarding (after step 2.2 but before completing all steps) Onboarding resumes at the last incomplete step; completed steps remain ticked □
2.10 Complete all four onboarding steps Checklist shows 100% complete; user is redirected (or prompted) to the main dashboard; all dashboard widgets are now active □

8
Known Limitations & Out-of-Scope Items
Do not raise these as bugs unless the behaviour differs from the description below. These are known environment constraints or features intentionally excluded from this test cycle.
  • PAYMENT Real payments are live by default. The production Paystack key processes actual card charges. QA testing must use the Paystack test key (pk_test_...) configured in the environment. Confirm with the backend team that the test environment is using the sandbox key before running any deposit tests.
  • SMS SMS notifications are not available in QA. OTP and transactional SMS messages use the Africa's Talking API, which requires a live paid key. In the QA environment, SMS sending will silently fail or log to console only. Verify SMS content via the Africa's Talking test dashboard if a staging key has been provisioned.
  • EMAIL Email notifications require the Resend API key. Without a valid RESEND_API_KEY environment variable, all outbound emails (welcome, deposit confirmation, support ticket updates, statements) will fail silently. Check server logs for [email] log lines to confirm the correct email would have been sent.
  • FICA FICA document approval is a manual admin action. Uploading FICA documents sets their status to "Pending Review"; approval or rejection must be performed by an admin in the back-office panel. Automated identity verification via a third-party API is not in scope for this test cycle.
  • OZOW Ozow sandbox requires a dedicated test merchant ID. If Ozow is not configured with a sandbox merchant ID in the QA environment, the Ozow redirect will fail at the gateway. Log this as an environment configuration issue, not a portal bug.
  • PERF Load and performance testing are out of scope for this guide. This document covers functional and UI correctness only. Concurrent-user and stress testing should be handled in a separate performance test plan against a dedicated load-test environment.
  • SECURITY Penetration testing and vulnerability scanning are out of scope for this guide. Security testing (OWASP Top 10, API security) should be performed in a dedicated security review cycle against a staging environment — never against production.
