◆ Platform Overview

Purpose of this document — Single source of truth for the entire SV Capital platform. All team members should refer to this before making any change to the codebase, business logic, or infrastructure. When rules here conflict with tribal knowledge, this document wins.
What the platform is
SV Capital
A South African alternative investment platform connecting retail investors to products across cattle, solar energy, SMME lending, gridfarmer, delivery bikes, and short-term instruments. Investors deposit via card (Paystack) or EFT (Ozow), invest into pooled products, and receive returns at maturity.
Production URL
https://svcapital-production.up.railway.app — serves both the API and all frontend files.
Staging URL
https://svcapital-staging.up.railway.app — used for testing before production deploys.
Tech stack at a glance
Frontend
Vanilla HTML/CSS/JS — no framework. Chart.js, jsPDF, html2canvas, QRCode.js from CDN.
Backend
Node 20 · Express 4 · PostgreSQL via pg (Railway-hosted)
Mobile
Capacitor 6 wrapping the investor portal as a native Android & iOS app.
Hosting
Railway (primary, Docker-based, full-stack) + Cloudflare Pages (static fallback, dist/).
Auth
JWT access tokens (30 min) + httpOnly refresh tokens stored as cookies. TOTP 2FA available for admin accounts.
Comms
Email: Resend (noreply@svcapital.co.za). SMS: Africa's Talking. Push: web-push & Capacitor push notifications.

⚠ Development Rules

These rules are non-negotiable. Every person touching this codebase — developer, admin, or AI assistant — must follow them without exception. Violations cause broken experiences for investors.
Git & branching
Push directly to main Critical
There are no feature branches. All changes — no matter how small — go directly to main. No pull requests. No review gates. Commit and push immediately after every change.
Commit message format
Use conventional commits: fix(mobile): description / feat(admin): description / chore: description. Keep the subject under 72 characters. Add a body when the why is non-obvious.
Version bumping — when and where
Why this matters. Browsers and the mobile app cache JS and CSS aggressively. Without a version bump, investors and staff will run stale code after a deploy. Always bump before committing a change to a JS or CSS file.
Web investor portal JS change portal/js/portal.js
Open portal/index.html, find js/portal.js?v=N, increment N by 1. Do this before the commit, not after.
Admin console JS change admin/js/admin.js
Open admin/index.html, find js/admin.js?v=N, check the current value, increment by 1. Never assume the version — always look it up first.
Mobile app JS or CSS change Both files must be bumped
1. mobile/www/index.html — bump js/portal.js?v=N
2. mobile/www/sw.js — bump const CACHE = 'svc-portal-vN'
Both must be bumped in the same commit. Missing the SW bump means installed app users get stale assets.
Shared js/api.js change
Bump the ?v=N query string in every HTML file that loads it: admin/index.html, portal/index.html, mobile/www/index.html. Check all three.
CSS versioning
Mobile CSS change (mobile-app.css, portal.css, portal-premium.css)
Bump the SW cache in mobile/www/sw.js AND bump the CSS query string in mobile/www/index.html (e.g. mobile-app.css?v=N).

⚠ Business Rules

These rules encode real money handling. Getting them wrong affects investor balances, compliance records, and trust. Every code path that touches investments, fees, or transactions must honour these rules.
Platform fee
1% platform fee on every investment Always negative
The platform charges 1% of the investment amount as a fee. Rules:

1. Fee = investment_amount × 0.01
2. Fee transactions must always display as a negative value in all transaction lists, investor statements, and exports. Never positive.
3. Recorded in the fee_ledger table and as a type: 'fee' transaction in transactions.
Sub-account invest gate
openSaInvest() — balance gate before marketplace navigation Critical
Before allowing a sub-account to invest, the function must verify:

wallet_balance ≥ min_investment + platform_fee

Where min_investment and platform_fee are derived from the cheapest currently open investment pool. If the condition is not met, the user must top up before proceeding. Never navigate to the marketplace without this check.
KYC / FICA requirements
Required KYC documents before investment
Investors must complete KYC before their first investment. Required:
• South African ID document or passport
• Selfie / liveness photo
• Proof of address (utility bill, bank statement — not older than 3 months)
• Bank account verification (via Stitch Money)
KYC status is tracked on the investors.kyc_status field. FICA annual re-checks are handled by ficaCron.js.
Maturity & payouts
Payout options at maturity
Investors choose one of four maturity instructions:
• reinvest — full amount reinvested into a new pool
• payout_all — capital + returns paid to bank account
• payout_return — only returns paid out; capital reinvested
• payout_custom — custom amount paid out; remainder reinvested

Processed nightly by maturityCron.js at 23:00 SAST.
Default product rates
Benchmark rate: 13% p.a. · Performance fee: 20% of excess returns above benchmark. Both can be overridden per product in the admin console.
Wallet & reconciliation
Transaction types
deposit — money added to wallet · withdrawal — money paid out to bank · investment — wallet deducted for investment · return — interest/return credited · payout — maturity payout credited · fee — platform fee deducted (always negative) · refund — cancelled investment refund · transfer — between accounts
Withdrawal approval
All withdrawals require admin approval before payment. Approvals trigger email + SMS notifications. Rejections require a reason from a provided template. Alert crons fire at 10:00, 13:00, and 16:00 SAST for pending withdrawals.

Build process
Building the mobile app
1. Run npm run build from mobile/ — executes scripts/build.js, copies portal assets into mobile/www/ and patches native API base URL.
2. Run npx cap sync android (or ios) to sync web assets into the native project.
3. For a release APK/AAB: npm run cap:build:android (runs Gradle bundleRelease).
Android signing keystore: mobile/android-config/uploadkeystore.jks.
WebView limitations & known workarounds
window.open(blobUrl) is blocked Known issue
Capacitor WebView blocks opening blob URLs via window.open(). Workaround: render content into an in-page full-screen overlay instead. File downloads use navigator.share({ files: [file] }).
window.print() is silent Known issue
The native WebView does not open a print dialog when window.print() is called. Workaround for statements: _handleSavePdf() uses html2canvas + jsPDF to generate a real PDF blob and shares it via navigator.share().
<a download> clicks may not trigger download
Programmatic anchor click-to-download is unreliable in Capacitor WebView on iOS. Always prefer navigator.share({ files: [...] }) for any file the user needs to save.
Preferred file sharing pattern on mobile
Build a Blob → wrap in a File → check navigator.canShare({ files: [file] }) → call navigator.share({ files: [file], title: '...' }). Triggers native iOS/Android share sheet. Supported on iOS 15+ and Android Chrome.

◆ Database Schema

Authoritative schema file: server/db/setup.js — 68 CREATE TABLE statements. Run via node server/db/setup.js to initialise a new database. Migrations are in server/db/migrate.js.
Core entities
investors
Primary investor record. Key fields: id, first_name, last_name, email, phone, id_number, dob, province, risk_profile, kyc_status, status, wallet_balance, total_invested, total_returns, referral_code, referred_by, ifa_id, archived_at.
sub_accounts
Sub-accounts linked to a parent investor via parent_investor_id. Types: business, trust, stokvel, minor, individual. Has own wallet_balance, kyc_status, and bank details.
investment_pools
Investment product pools. Key fields: product_type, status (open/active/matured), target_amount, raised_amount, min_investment, annual_rate, term_months, start_date, end_date, maturity_summary (JSONB).
investments
Individual investor positions. Links investor_id → pool_id. Key fields: amount, status, expected_return, actual_return, payout_option, sub_account_id, maturity_instruction, maturity_processed_at.
transactions
All money movements. Links to investor_id, optionally investment_id, pool_id, sub_account_id. Types: deposit, withdrawal, investment, return, payout, fee, refund, transfer. Fee transactions are always stored and displayed as negative amounts.
products
Product catalogue. One row per product type. Key fields: product_type (unique), label, min_investment, term_months, benchmark_rate, performance_fee_pct, is_active, display_on_homepage, color, factsheet_url.

◆ Deployment

Railway (primary)
How it works
Railway builds from the Dockerfile (multi-stage Node 20 Alpine). The Express server at server/index.js serves both the API (/api/*) and all static files (HTML, CSS, JS, assets) from the repo root.

Healthcheck: GET /api/health — must return 200. Railway restarts the service on failure (max 10 retries).

Production: https://svcapital-production.up.railway.app
Staging: https://svcapital-staging.up.railway.app
Trigger a deploy
Push any commit to main. Railway auto-detects the push via its GitHub integration and triggers a new build and deploy. No manual steps required.
Config: railway.toml
builder = DOCKERFILE · healthcheckPath = /api/health · healthcheckTimeout = 30 · restartPolicyType = ON_FAILURE · restartPolicyMaxRetries = 10
Cloudflare Pages (static fallback)
How it works
The dist/ directory is a committed snapshot of all frontend files. Cloudflare Pages serves these. API calls are proxied to Railway via dist/_redirects.

To rebuild: npm run pages:build from the root — copies everything into dist/. Commit and push to deploy.
Mobile release build
Android release APK/AAB
1. Update version in mobile/android/app/build.gradle (versionCode, versionName)
2. Run npm run build from mobile/
3. Run npx cap sync android
4. Run npm run cap:build:android — Gradle bundleRelease
Signing key: mobile/android-config/uploadkeystore.jks — keep this file safe, never commit key credentials.
iOS release
1. Run npm run build from mobile/
2. Run npx cap sync ios
3. Open mobile/ios/App/App.xcworkspace in Xcode
4. Archive and upload via Xcode Organizer
