Firebase Data Migration

Upload any combination of the JSON export files from the previous platform. All files are optional — only the data you provide will be imported. Safe to run multiple times — existing records are updated, not duplicated. userAccountNumber is always the unique identifier.

Post-Migration Utilities

Recalculate Pool Statistics

Recomputes investor_count, raised_amount, and current_invested for every pool from live investment data. Safe to run at any time.

Fix SMME → Short Term Product Type

Renames product_type = 'smme' to 'short_term' across pools, investments, and products immediately. Idempotent — safe to run multiple times.

Backfill Orphan Pool Records

Finds any investments that reference a pool_id with no matching pool record (e.g. pools that were in Firebase but missing from the JSON export) and automatically creates stub pool records from the investment data. Safe to run multiple times.

Backfill FICA Approval from KYC Status

Finds every investor whose kyc_status is already approved and sets their fica_status to approved and account to active. Also syncs the reverse direction. Safe to run multiple times.

Re-import Bank Accounts from JSON

Upload the bankAccounts JSON export from Firebase to populate the dedicated bank columns (bank_name, bank_account_number, etc.) for all matching investors. Only ACTIVE accounts are imported; defaults to the account flagged defaultAccount.

Promote from Existing Notes

If bank data was stored in the notes JSON column during a previous migration, promote it to the dedicated columns without needing a new file upload. Only fills null columns — never overwrites existing data.

Platform Overview

Purpose of this handbook — Single source of truth for the entire SV Capital platform. All team members must refer here before making any change to the codebase, business logic, or infrastructure. When rules here conflict with tribal knowledge, this document wins.
What the platform is
SV Capital
A South African alternative investment platform connecting retail investors to products across cattle, solar energy, SMME lending, gridfarmer, delivery bikes, and short-term instruments. Investors deposit via card (Paystack) or EFT (Ozow), invest into pooled products, and receive returns at maturity.
Production URL
https://svcapital-production.up.railway.app — serves both the API and all frontend files.
Staging URL
https://svcapital-staging.up.railway.app — used for testing before production deploys.
Tech stack at a glance
Frontend
Vanilla HTML/CSS/JS — no framework. Chart.js, jsPDF, html2canvas, QRCode.js from CDN.
Backend
Node 20 · Express 4 · PostgreSQL via pg (Railway-hosted).
Mobile
Capacitor 6 wrapping the investor portal as a native Android & iOS app.
Hosting
Railway (primary, Docker-based, full-stack) + Cloudflare Pages (static fallback, dist/).
Auth
JWT access tokens (30 min) + httpOnly refresh tokens stored as cookies. TOTP 2FA available for admin accounts.
Comms
Email: Resend (noreply@svcapital.co.za). SMS: Africa's Talking. Push: web-push & Capacitor push notifications.

Development Rules

These rules are non-negotiable. Every person touching this codebase must follow them. Violations cause broken experiences for investors.
Git & branching
Push directly to main Critical
There are no feature branches. All changes — no matter how small — go directly to main. No pull requests. No review gates. Commit and push immediately after every change.
Commit message format
Use conventional commits: fix(mobile): description · feat(admin): description · chore: description. Subject under 72 characters.
Version bumping — when and where
Why this matters. Browsers and the mobile app cache JS and CSS aggressively. Without a version bump, investors and staff run stale code after a deploy. Always bump before committing.
Web investor portal JS change portal/js/portal.js
Open portal/index.html, find js/portal.js?v=N, increment N by 1. Do this before the commit, not after.
Admin console JS change admin/js/admin.js
Open admin/index.html, find js/admin.js?v=N, check the current value, increment by 1. Never assume — always look it up first.
Mobile app JS or CSS change Both files must be bumped
1. mobile/www/index.html — bump js/portal.js?v=N
2. mobile/www/sw.js — bump const CACHE = 'svc-portal-vN'
Both must be bumped in the same commit. Missing the SW bump means installed app users get stale assets.
Shared js/api.js change
Bump the ?v=N query string in every HTML file that loads it: admin/index.html, portal/index.html, mobile/www/index.html. Check all three.

Business Rules

These rules encode real money handling. Getting them wrong affects investor balances, compliance records, and trust.
Platform fee
1% platform fee on every investment Always negative
Fee = investment_amount × 0.01
Fee transactions must always display as a negative value in all transaction lists, investor statements, and exports — never positive.
Recorded in the fee_ledger table and as a type: 'fee' transaction in transactions.
Sub-account invest gate
openSaInvest() — balance gate before marketplace navigation Critical
Before allowing a sub-account to invest, verify:

wallet_balance ≥ min_investment + platform_fee

Where min_investment is from the cheapest currently open pool. If the condition is not met, prompt the user to top up. Never navigate to the marketplace without this check.
KYC / FICA requirements
Required before first investment
• South African ID document or passport
• Selfie / liveness photo
• Proof of address (not older than 3 months)
• Bank account verification (Stitch Money)
Status tracked on investors.kyc_status. Annual re-check via ficaCron.js.
Maturity & payouts
Payout options
reinvest — full amount reinvested into a new pool
payout_all — capital + returns paid to bank account
payout_return — only returns paid out; capital reinvested
payout_custom — custom amount paid out; remainder reinvested

Processed nightly by maturityCron.js at 23:00 SAST.
Default product rates
Benchmark rate: 13% p.a. · Performance fee: 20% of excess returns above benchmark. Both can be overridden per product in Admin → Products.
Transaction types
All transaction types
deposit — money added to wallet · withdrawal — money paid out to bank · investment — wallet deducted · return — interest/return credited · payout — maturity payout credited · fee — platform fee deducted (always negative) · refund — cancelled investment refund · transfer — between accounts
Withdrawal approval
All withdrawals require admin approval before payment. Rejections require a reason from the provided templates. Alert crons fire at 10:00, 13:00, and 16:00 SAST for pending withdrawals.

Build process
Building and releasing
1. npm run build from mobile/ — copies portal assets into mobile/www/ and patches native API URL.
2. npx cap sync android (or ios) to sync web assets into the native project.
3. For Android release: npm run cap:build:android (Gradle bundleRelease).
4. For iOS release: open mobile/ios/App/App.xcworkspace in Xcode, Archive, upload via Organizer.
Android signing keystore: mobile/android-config/uploadkeystore.jks — never commit credentials.
WebView limitations & workarounds
window.open(blobUrl) is blocked Known
Capacitor WebView blocks opening blob URLs. Workaround: render content into a full-screen in-page overlay. File downloads use navigator.share({ files: [file] }).
window.print() is silent Known
The WebView does not open a print dialog. Workaround for statements: _handleSavePdf() uses html2canvas + jsPDF to generate a real PDF blob and shares it via navigator.share().
Preferred file-sharing pattern on mobile
Build a Blob → wrap in a File → check navigator.canShare({ files: [file] }) → call navigator.share({ files: [file], title: '...' }). Supported on iOS 15+ and Android Chrome.

Deployment

Railway (primary)
How it works
Railway builds from Dockerfile (multi-stage Node 20 Alpine). The Express server serves both the API (/api/*) and all static files.

Healthcheck: GET /api/health — must return 200. Auto-restart on failure (max 10 retries).

Push any commit to main → Railway auto-detects via GitHub integration → builds and deploys. No manual steps.
Config: railway.toml
builder = DOCKERFILE · healthcheckPath = /api/health · healthcheckTimeout = 30 · restartPolicyType = ON_FAILURE · restartPolicyMaxRetries = 10
Cloudflare Pages
How it works
dist/ is a committed snapshot of all frontend files. Cloudflare Pages serves these. API calls are proxied to Railway via dist/_redirects.
To rebuild: npm run pages:build → commit dist/ → push.
Mobile release
Android & iOS release steps
Android: Update versionCode/versionName in mobile/android/app/build.gradle → npm run build → npx cap sync android → npm run cap:build:android. Signing key: mobile/android-config/uploadkeystore.jks.

iOS: npm run build → npx cap sync ios → open App.xcworkspace in Xcode → Archive → upload via Organizer.
